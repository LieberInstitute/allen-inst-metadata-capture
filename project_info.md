# Project Info: AIND Metadata Capture

## Purpose

This repository is a prototype metadata capture system for the Allen Institute for Neural Dynamics (AIND).

Its core idea is simple: a scientist describes an experiment in chat or uploads experiment files, and a Claude-powered agent extracts structured metadata into AIND-shaped records. The system validates those records against local schema rules, AIND schema enums, AIND's live metadata database, and external biology registries.

The product is not a general chatbot. It is a focused metadata workbench for creating, reviewing, linking, validating, and confirming experimental metadata records.

## Main Concepts

- Conversational capture: scientists provide natural language, images, PDFs, spreadsheets, documents, audio, or video.
- Granular records: metadata is split into typed records instead of one large JSON blob.
- Shared records: subjects, procedures, instruments, and rigs can be reused across sessions.
- Asset records: sessions, acquisitions, data descriptions, processing, and quality control are tied to a specific data asset.
- Record links: records are connected with explicit bidirectional links.
- Validation loop: each captured record is validated and validation results are streamed back into the chat UI.
- Registry enrichment: selected biological identifiers trigger lookups against Addgene, NCBI Gene, and MGI.
- AIND live data access: the agent can query AIND production metadata through the bundled MCP server.

## Architecture

The repository has four main parts:

- `agent/`: Python FastAPI backend and Claude Agent SDK integration.
- `frontend/`: Next.js 14, React, TypeScript, Tailwind UI.
- `aind-data-mcp/`: bundled MCP server for read-only AIND metadata database access.
- `evals/`: deterministic, network, and LLM-graded tests.

Typical flow:

1. User sends a chat message and optional attachments from the frontend.
2. The frontend uploads files first, then sends attachment references to `/chat`.
3. The backend stores the user turn and gathers session history, current records, and upload extraction results.
4. The Claude Agent SDK runs with a system prompt plus MCP tools.
5. The agent calls local capture tools to save or update records.
6. The capture tool validates records, updates the database, and streams validation results.
7. The backend streams text, tool events, validation events, and artifacts to the frontend.
8. The frontend updates the chat, metadata sidebar, dashboard, and artifact viewer.

## Backend

The backend entry point is `agent.server:app`, usually run through `python -m agent.run`.

Important endpoints:

- `POST /chat`: SSE chat stream.
- `GET /records`: list metadata records.
- `GET /records/{id}`: fetch one record and links.
- `PUT /records/{id}`: update record JSON.
- `PATCH /records/{id}/field`: update one schema-aware field.
- `POST /records/{id}/confirm`: mark a record confirmed.
- `POST /records/link`: link records.
- `GET /sessions`: list chat sessions.
- `GET /sessions/{id}/messages`: fetch session conversation history.
- `POST /upload`: upload a file.
- `POST /upload/init`, `/upload/chunk`, `/upload/finalize`: chunked upload path.
- `GET /uploads/{id}/extraction`: poll extraction status.
- `GET /uploads/{id}/table`: parse a spreadsheet for preview.
- `GET /artifacts/{id}`: fetch an agent-rendered artifact.
- `GET /models`: list supported Claude models.
- `GET /health`: backend and transcription availability.

Database selection is environment-driven:

- If `DATABASE_URL` is set, the app uses PostgreSQL via `asyncpg`.
- Otherwise it uses SQLite via `aiosqlite` at `agent/metadata.db` or `METADATA_DB_DIR/metadata.db`.

The current README still emphasizes SQLite. The code and `replit.md` show the current behavior is dual PostgreSQL/SQLite.

## Database Model

Core tables:

- `metadata_records`: typed metadata records with `record_type`, `category`, JSON data, status, and validation JSON.
- `record_links`: many-to-many links between records.
- `conversations`: persisted chat turns and attachment metadata.
- `uploads`: uploaded file metadata, raw bytes for smaller files, extracted text, extraction status.
- `upload_keyframes`: video keyframes stored one row per frame.
- `artifacts`: persistent tables, JSON, markdown, or code generated by the agent.

Record types:

- Shared: `subject`, `procedures`, `instrument`, `rig`.
- Asset-specific: `data_description`, `acquisition`, `session`, `processing`, `quality_control`.

## LLM And Agent Implementation

The agent uses `claude-agent-sdk` and the Claude Code CLI. The default model in code is `claude-sonnet-4-6`, with Opus and Haiku alternatives exposed by `/models`.

The system prompt in `agent/prompts/system_prompt.py` defines:

- AIND record categories and field mappings.
- When to create each record type.
- How to avoid duplicate shared records.
- How to link related records.
- Required validation behavior.
- Registry lookup behavior.
- Attachment handling rules.
- When to use local capture tools versus live AIND database tools.

Allowed tools are intentionally narrow:

- Built-in: `Read`, `WebSearch`.
- Local MCP server `capture`: `capture_metadata`, `find_records`, `link_records`, `render_artifact`.
- AIND MCP server `aind-data-mcp`: read-only query, count, aggregation, schema, modality, project, and example tools.

The app supports two execution paths:

- Standard path: `query()` spawns a Claude SDK process per request.
- Warm pool path: `SDKClientPool` keeps a `ClaudeSDKClient` and MCP subprocesses alive when `USE_SDK_POOL=1`.

The pool includes a watchdog that periodically starts a fresh `aind-data-mcp` subprocess, initializes MCP, lists tools, and forces reconnects if the MCP server is unhealthy or stale.

## Local Capture Tools

`agent/tools/capture_mcp.py` defines the local MCP tools.

`capture_metadata`:

- Requires `session_id`, `record_type`, and JSON `data`.
- Creates or updates exactly one record type.
- Auto-assigns category from `CATEGORY_MAP`.
- Auto-enriches known species with NCBI taxonomy registry info.
- Optionally links to another record.
- Runs schema validation.
- Stores validation JSON.
- Pushes validation events into the streaming queue.
- Runs registry lookups when relevant.

`find_records`:

- Searches local records by type, category, and text.
- Used to reuse shared records.
- Does not query the AIND production database.

`link_records`:

- Creates bidirectional semantic links through the `record_links` table.

`render_artifact`:

- Persists table, JSON, markdown, or code output as a clickable artifact.
- Streams artifact events to the frontend.

## AIND MCP Server

The bundled `aind-data-mcp` package is an MCP server targeting AIND V2 metadata schema.

The app registers it as a stdio MCP server by running:

```bash
python -m aind_data_mcp.data_access_server
```

with `PYTHONPATH` pointed at `aind-data-mcp/src`.

The MCP server uses `aind_data_access_api.document_db.MetadataDbClient` with:

```python
host="api.allenneuraldynamics.org"
version="v2"
```

Main exposed tool groups:

- Data queries: `get_records`, `count_records`, `aggregation_retrieval`.
- Schema help: `get_top_level_nodes`, `get_additional_schema_help`, `get_modality_types`.
- Examples: `get_subject_example`, `get_procedures_example`, `get_data_description_example`, `get_instrument_example`, `get_acquisition_example`, `get_processing_example`, `get_quality_control_example`.
- Resources: `resource://aind_api`, `resource://load_nwbfile`.

The upstream MCP package also contains NWB/S3 tools, but this app intentionally does not import or allow them in the active agent path because they pull in heavier dependencies such as `boto3` and `hdmf_zarr` and slow cold start.

## AWS Relationship

This repository has limited direct AWS integration in the active application.

Active code:

- No CDK, Terraform, CloudFormation, Lambda, ECS, S3 upload pipeline, Bedrock calls, or AWS deployment code was found.
- The backend queries AIND metadata through `api.allenneuraldynamics.org` using the AIND data access API, not direct AWS SDK calls.
- Local uploads are stored on disk and, for smaller files, duplicated into the app database for durability.
- Deployment notes are mainly about Replit, PostgreSQL, proxy buffering, and chunked uploads.

Indirect or inactive AWS-related pieces:

- AIND data assets can include `location` fields such as S3 paths.
- `aind-data-mcp/src/aind_data_mcp/nwb_tools.py` contains S3/NWB helpers using `boto3`, but `data_access_server.py` does not import that module and the agent does not allow those tools.
- The MCP README documents `identify_nwb_contents_with_s3_link`, but this app excludes it from the active tool list.

Practical interpretation: AWS is relevant as part of the broader AIND data ecosystem, especially S3-hosted data assets and possible DocumentDB/MongoDB infrastructure behind the AIND API. The repository itself is currently an application-layer agent, web UI, and metadata database, not an AWS infrastructure project.

## Bioinformatics And Genomics Concepts

The system is neuroscience metadata focused, with several biological and genomic validation hooks.

Schema and metadata:

- `aind-data-schema`: canonical AIND Pydantic schema.
- `aind-data-schema-models`: controlled vocabulary models for modality and species.
- Pydantic model introspection builds known fields and enum sets at import time.
- Subject species are enriched with NCBI taxonomy registry identifiers.

Biology registries:

- Addgene: plasmid and viral vector search by name or catalog number.
- NCBI Gene: gene symbol, gene name, or Gene ID lookup through E-utilities.
- MGI: Mouse Genome Informatics quick search for mouse genes and alleles.

Metadata examples include:

- Subject IDs, species, sex, genotype, alleles.
- Injection materials, viral constructs, plasmids.
- Stereotactic coordinates and procedure protocols.
- Instrument components, lasers, detectors, objectives, cameras, rigs.
- Acquisition streams, stimulus epochs, behavior metrics.
- Processing pipelines and quality control metrics.

Supported modalities include behavior, behavior videos, confocal, EMG, ecephys, fiber photometry, fMOST, icephys, ISI, MRI, merfish, pophys, slap2, SPIM, BARseq, EM, MAPseq, STPT, brightfield, and scRNAseq.

## Data Formats

Uploaded files:

- Native to Claude: PNG, JPEG, GIF, WebP, PDF.
- Text extraction: TXT, Markdown, JSON, YAML, Python files, logs.
- Spreadsheets: CSV, XLSX, XLS.
- Documents: DOCX.
- Audio: MP3, WAV, M4A, OGG.
- Video: MP4, MOV, WebM, MKV.

Internal data formats:

- Metadata records are stored as JSON in SQL text columns.
- Validation results are stored as JSON.
- Agent artifacts are stored as JSON.
- Video keyframes are stored as PNG bytes in `upload_keyframes`.
- Spreadsheet previews are normalized to `{columns, rows, total_rows, sheet_name}`.

Specialized scientific formats:

- NWB and NWB-Zarr support exists in the bundled MCP package, including references to `pynwb`, `hdmf_zarr`, `NWBZarrIO`, and Code Ocean `/data` layouts.
- NWB tools are not active in the app's allowed agent tool list.

## Upload And Extraction Tooling

The upload pipeline is intentionally asynchronous.

Small files:

- Go through `POST /upload`.
- Native images/PDFs are marked `done` immediately.
- Other types are stored, then background extraction starts.

Large files:

- Frontend splits files larger than 8 MB into 5 MB chunks.
- Backend reassembles through `/upload/init`, `/upload/chunk`, and `/upload/finalize`.
- This avoids Replit reverse-proxy body limits.

Extraction:

- Text is read and truncated at 50,000 characters.
- Spreadsheets are parsed and rendered as markdown tables, capped at 100 rows.
- DOCX extraction reads paragraph text through `python-docx`.
- Audio uses `ffmpeg` to normalize to 16 kHz mono WAV, then `whisper-cli` with `ggml-base.en.bin`.
- Video keyframes use PyAV to open the container once, seek to representative timestamps, resize frames, and store PNG bytes one frame per row.
- Video transcription runs separately and can land after keyframes are already usable.

Health:

- `/health` reports whether transcription dependencies are available.
- Audio upload fails fast if `ffmpeg`, `whisper-cli`, or the model file is missing.
- Video upload requires `ffmpeg`; transcript is optional if whisper is unavailable.

## Frontend

The frontend is a Next.js app in `frontend/`.

Major UI pieces:

- `page.tsx`: main chat and metadata view.
- `dashboard/page.tsx`: review dashboard.
- `ChatPanel.tsx`: streaming chat, file upload, tool progress, background stream behavior.
- `MetadataSidebar.tsx`: record display grouped by type.
- `AppSidebar.tsx`: navigation, sessions, health indicator.
- `EditableTableView.tsx` and `SpreadsheetViewer.tsx`: grid and artifact editing.
- `ArtifactModal.tsx`: full-screen artifact viewer.
- `ModelPicker.tsx`: model selector.

Transport:

- Local/non-Replit: SSE over `/chat`.
- Replit-like hosts: browser opens `/ws/chat`; `frontend/server.mjs` bridges WebSocket frames to backend SSE because Replit buffers SSE responses.

API proxy:

- `frontend/next.config.mjs` rewrites frontend paths such as `/chat`, `/records`, `/sessions`, `/uploads`, and `/artifacts` to backend `localhost:8001`.
- `NEXT_PUBLIC_API_URL` controls whether the browser uses a direct backend URL or same-origin rewrites.

## Validation Tooling

Validation combines schema-derived and hand-written rules.

Schema-derived:

- Known fields are introspected from `aind-data-schema` Pydantic models.
- Valid modalities, species, and sex values are imported from schema models when installed.
- Inline fallbacks exist if schema packages are unavailable.

Hand-written:

- Required fields per record type.
- Subject ID format warning.
- Sex enum validation.
- Species warning.
- Modality validation.
- Session start/end ordering.
- Procedure coordinate and section thickness checks.
- Instrument ID, modality, component, and modification date checks.

Validation output includes:

- `status`: `valid`, `warnings`, or `errors`.
- `completeness_score`.
- `errors`.
- `warnings`.
- `missing_required`.
- `valid_fields`.

## Testing And Evals

The `evals/` directory covers several risk levels:

- Deterministic tests for validation, field patching, service wiring, extraction helpers, and end-to-end API paths.
- Network tests for Addgene, NCBI Gene, and MGI registry lookups.
- LLM extraction tests that run the full agent and verify database state.
- LLM-graded conversation tests using rubric-based scoring.
- Agent end-to-end tests combining deterministic DB checks and response-quality judging.

Common commands from the docs:

```bash
python3 -m pytest evals/ -x -q --ignore=evals/tasks/extraction/
python3 -m pytest evals/tasks/extraction/ -v -m llm
python3 -m pytest evals/tasks/conversation/ -v -m llm
python3 -m pytest evals/tasks/validation/ -v -m network
python3 -m pytest evals/tasks/agent/ -v -m llm
```

Frontend tests use Vitest:

```bash
cd frontend
npm run test
```


Frontend:

```bash

npm install

```

Open:

```text

```

Important environment variables:

- `ANTHROPIC_API_KEY`: required for agent calls.
- `DATABASE_URL`: enables PostgreSQL.
- `METADATA_DB_DIR`: SQLite database directory override.
- `UPLOADS_DIR`: upload storage directory.
- `USE_SDK_POOL=1`: enables the warm Claude SDK pool.
- `SKIP_AIND_MCP=1`: disables the live AIND MCP server.
- `AIND_MCP_PYTHON`: Python executable used for the AIND MCP subprocess.
- `NEXT_PUBLIC_API_URL`: frontend API base override.

## Implementation Notes And Tradeoffs

- The app saves partial metadata early instead of waiting for complete records.
- Local capture is separated from production AIND querying to avoid confusing local drafts with live assets.
- The database abstraction uses `?` placeholders everywhere and converts them to PostgreSQL `$1`, `$2`, etc.
- File extraction happens at upload time so chat requests do not block on transcription or parsing.
- Video processing is memory-conscious: keyframes are stored one at a time instead of as a large JSON blob.
- Warm SDK pooling improves time to first token but adds reconnection and MCP health-check complexity.
- Replit WebSocket bridging exists only to bypass proxy buffering of SSE.
- The active app currently has read-only access to AIND live metadata; write-back to AIND MongoDB is not implemented.
- Authentication is not implemented.
